# User Directory

Учебный проект на Go: загружает случайных пользователей из открытого API
[randomuser.me](https://randomuser.me), сохраняет их в SQLite и показывает
карточку пользователя в браузере по ID.

## Возможности

- постраничная загрузка пользователей с повторами при временных ошибках API;
- сохранение в SQLite через upsert по email (без дублей);
- дедупликация записей перед записью в базу;
- веб-интерфейс с формой поиска на главной (ID не попадает в URL);
- тесты для HTTP-клиента, хранилища и сервера.

## Технологии

- Go 1.26
- только стандартная библиотека для сети и шаблонов (`net/http`, `html/template`);
- SQLite через `modernc.org/sqlite` — чистый Go, без CGO.

## Структура

```
main.go                 загрузка данных из API в базу
cmd/server/             запуск HTTP-сервера
clients/                клиент randomuser.me
storage/                работа с SQLite
server/                 HTTP-обработчики и шаблоны
model/                  общий тип User
```

## Требования

- Go 1.26 или новее.

## Запуск

### 1. Загрузить данные

```
go run . -limit 500 -db users.db
```

Флаги загрузчика:

| Флаг | По умолчанию | Описание |
|------|--------------|----------|
| `-limit` | `1000` | сколько пользователей загрузить |
| `-page-size` | `100` | размер одной страницы запроса |
| `-db` | `users.db` | файл базы данных |
| `-seed` | случайный | seed для воспроизводимой загрузки |

Seed печатается в лог, поэтому загрузку можно повторить один в один:
`go run . -seed=<seed> -db users.db`.

### 2. Запустить сервер

```
go run ./cmd/server -db users.db -addr :8080
```

Флаги сервера: `-db` (файл базы) и `-addr` (адрес, по умолчанию `:8080`).

Откройте http://localhost:8080, введите ID пользователя (например, `1`) и
нажмите «Найти».

## Как это работает

Загрузчик ходит по страницам API, собирает пользователей и сохраняет их одной
транзакцией. Уникальность обеспечивает колонка `email`. Сервер читает того же
пользователя из базы по `id` и отдаёт HTML-страницу. Поиск выполняется через
`POST`, поэтому ID не отражается в адресной строке.

## Замечания

- API иногда выдаёт двух разных людей с одинаковым email, поэтому часть записей
  перед сохранением схлопывается.
- Включён режим WAL: рядом с файлом базы могут появляться `users.db-wal` и
  `users.db-shm`. При копировании базы берите и их.
